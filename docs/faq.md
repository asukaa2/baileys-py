# FAQ

## Is this an official WhatsApp library?

No. baileys-py is a community port of [Baileys](https://github.com/whiskeysockets/Baileys),
which is itself a community project. WhatsApp (Meta) does not
officially support either.

## Is using baileys-py against WhatsApp's ToS?

WhatsApp's Terms of Service prohibit automated access through
non-official clients. Using baileys-py on a personal account may get
the account banned. We're not lawyers — read the ToS yourself and make
your own decision.

For business use, consider the official [WhatsApp Business API](https://business.whatsapp.com/).

## Does it work on multi-device?

Yes — baileys-py targets the multi-device protocol (the same one
upstream Baileys uses). The old mobile-only API has been removed in
upstream Baileys and is not supported here either.

## Does it work without a phone?

After you scan the QR (or use a pairing code once), the linked device
runs independently — you can turn off the phone. Multi-device means
the linked-device session has its own credentials and talks directly
to WA servers.

## Can I run many accounts at once?

Yes. Each account needs its own `auth_info` folder:

```python
state1, save1 = await use_multi_file_auth_state("./acc1")
state2, save2 = await use_multi_file_auth_state("./acc2")

sock1 = make_wa_socket(auth=state1, push_name="Bot 1")
sock2 = make_wa_socket(auth=state2, push_name="Bot 2")
```

Run them in the same process with `asyncio.gather`, or in separate
processes for isolation.

## Can I send media (images, audio, video)?

Yes, via the high-level API (`sock.send_message(jid, {"image": {...}})`).
The actual media upload to WA's media servers requires the WA protobuf
schema — see [Internals](internals.md#extending-baileys-py).

## Can I receive media?

Same answer — the `messages.media-update` event fires when media is
available, but decrypting the media blob requires the WA
media-decryption helpers (which need WAProto).

## Can I make phone calls?

Receiving calls is supported at the event level (`call` event). Making
calls is not supported (and WhatsApp does not officially expose this
to linked devices).

## Does it support newsletters / channels?

The IQ stanzas are built (`baileys_py.messages` doesn't have newsletter
helpers yet, but the binary protocol layer can encode the IQs). Full
newsletter interop requires the WA protobuf schema.

## Can I use it with a proxy?

Pass `agent=` to `SocketConfig`. The `websockets` library accepts an
`httpx`-style proxy via `additional_headers` / `origin`:

```python
# Example using a SOCKS proxy via websockets' built-in support
# (you may need additional deps for your specific proxy type)
sock = make_wa_socket(
    auth=state,
    wa_websocket_url="wss://web.whatsapp.com/ws/chat",
)
```

For HTTP proxies, set the `HTTPS_PROXY` environment variable before
launching your script — `websockets` respects it.

## What Python versions are supported?

Python 3.9 and newer. We use `dataclasses`, `asyncio.ensure_future`,
`typing.Optional[...]` style annotations, and a few `__future__`
imports — all stable since 3.9.

## Will baileys-py work on Raspberry Pi / Termux / Alpine?

Yes, as long as:

* Python 3.9+ is available
* `pip install cryptography` succeeds (manylinux wheels cover armv7+)

On Alpine you may need `apk add libffi-dev openssl-dev python3-dev`.

## Why is the binary constants file so big?

`baileys_py/binary/constants.py` is 28 KB / ~1,300 lines because it
embeds WA's full single-byte (236) and double-byte (4×256) token
dictionaries. The encoder needs all of them. The file is
auto-generated by `scripts/build_constants.py`.

## Does baileys-py log my messages?

No. The logger emits connection / debug info to stderr, never message
contents. To be sure, set the log level to `WARN`:

```python
from baileys_py import Logger
sock = make_wa_socket(auth=state, logger=Logger("baileys", level="warn"))
```

## Is there a sync (non-async) API?

No. The whole package is async — you have to use `asyncio.run(main())`
or equivalent. A sync wrapper would be a thin shim that hides the event
loop; we'd rather let you control it.

## Can I use it in a Jupyter notebook?

Yes — Jupyter already runs an event loop, so `await sock.connect()`
works directly in a cell. Just remember to call `await sock.disconnect()`
before restarting the kernel.

## How do I get help?

* File an issue: <https://github.com/asukaa2/baileys-py/issues>
* Read the docs: this folder
* Read the upstream Baileys docs: <https://github.com/whiskeysockets/Baileys>

## How do I contribute?

PRs welcome. Areas that especially need work:

* **WAProto integration** — wire in the WhatsApp protobuf schema and
  enable real message encryption / decryption.
* **Signal ratchet** — implement the full Signal session / sender-key
  ratchet (or wrap `python-axolotl`).
* **More helpers** in `baileys_py/messages.py` — newsletter, business,
  catalog, payments.
* **Docs** — translate more upstream Baileys examples.

See [Internals → Extending baileys-py](internals.md#extending-baileys-py)
for the recommended extension points.

## How often is baileys-py updated?

We track upstream Baileys releases and port the relevant changes. If
WA bumps the protocol version, regenerate the binary constants:

```bash
python scripts/build_constants.py
```

## Why "baileys-py"?

The upstream library is called "Baileys" (a brand of Irish cream
liqueur, presumably because the original author liked it). The `-py`
suffix is the standard Python community convention for Python ports
(e.g. `requests-py`, `aiohttp-py`).

## Is there a type stub package?

`baileys_py/py.typed` is included, so `mypy` and `pyright` pick up
inline types automatically. No separate stub package needed.
